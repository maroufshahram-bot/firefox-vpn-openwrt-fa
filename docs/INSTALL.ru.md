# Установка

[English](INSTALL.md) · [فارسی](INSTALL.fa.md) · [Русский](INSTALL.ru.md) · [العربية](INSTALL.ar.md) · [Совместимость](COMPATIBILITY.ru.md)

## Перед началом

- Нужны прошивка семейства OpenWrt, LuCI, procd, поддерживаемая архитектура, права root и не менее 40 МБ свободного постоянного хранилища; для крупных файлов может понадобиться больше.
- Нужны аккаунт Mozilla / Firefox, доступ к его почте и возможность пройти проверки.
- Роутер должен иметь доступ в Интернет. Доступность аккаунта и серверов не гарантируется.
- Для перенаправления трафика клиентов LAN установите PassWall2 отдельно.
- Сохраните возможность вернуться к рабочему узлу. Установщик не меняет firewall, сеть, DNS или настройки PassWall2.

Не устанавливайте поверх работающей старой версии `test1`: автоматического переноса нет. Новый установщик ещё не проверен на реальном роутере.

**Язык установщика:** исходный код поддерживает `--lang en`, `fa`, `ru`, `ar`. Опубликованные архивы **v0.2.0-rc.1** содержат старый установщик: в командах ниже используйте `en`. Для новой сборки с русским переводом замените `--lang en` на `--lang ru`. Не заменяйте отдельные файлы внутри старого архива.

## 1. Подключение

Используйте SSH с компьютера, телефона или другого устройства:

```sh
ssh root@ROUTER_ADDRESS
```

Замените `ROUTER_ADDRESS` своим адресом локально, не публикуя его. Подойдёт и уже установленный терминал LuCI. Используйте доверенную LAN или существующий защищённый канал управления; открывать WAN-порты не нужно.

## 2. Загрузка, проверка и передача

Выберите правильный архив процессора из успешной сборки или проверенного релиза вместе с соответствующим `.sha256`. В папке загрузки на компьютере:

```sh
sha256sum -c firefox-vpn-openwrt-v0.2.0-rc.1-linux-armv7.tar.gz.sha256
```

Пример для ARMv7; для другой архитектуры измените имя файла. Контрольная сумма проверяет целостность, но сама по себе не доказывает доверие к издателю.

Передайте архив в `/root` через файловый менеджер LuCI, WinSCP или SCP:

```sh
scp firefox-vpn-openwrt-v0.2.0-rc.1-linux-armv7.tar.gz root@ROUTER_ADDRESS:/root/
```

При ошибке об отсутствии SFTP используйте `scp -O` или другой способ. Не загружайте архив через Flash Firmware, Restore Backup или менеджер пакетов.

## 3. Предварительная проверка

На роутере:

```sh
cd /root
tar -xzf firefox-vpn-openwrt-v0.2.0-rc.1-linux-armv7.tar.gz
cd firefox-vpn-openwrt
sh install.sh --lang en --check
```

Если модель, версия прошивки или target отличаются от точной эталонной комбинации:

```sh
sh install.sh --lang en --experimental --check
```

`--check` ничего не устанавливает. Успех не подтверждает маршрутизацию, вход, восстановление после перезагрузки или совместимость. Семейства вне OpenWrt/ImmortalWrt отклоняются даже с `--experimental`. GL.iNet должен определяться как допустимое семейство OpenWrt и иметь необходимые службы; названия бренда недостаточно.

## 4. Установка

Для эталонной платформы:

```sh
sh install.sh --lang en
```

Для экспериментальной платформы после осознанного принятия ограничений:

```sh
sh install.sh --lang en --experimental
```

Аккаунты сохраняются. Новая установка привязывает SOCKS к `127.0.0.1:10810`, а HTTP-панель — к LAN IPv4 на порту `10820`. Существующая конфигурация не перезаписывается: проверьте привязки. При сбое после замены файлов установщик пытается восстановить прежние управляемые файлы. Это не полная резервная копия роутера и не перенос данных.

Прочитайте начальные реквизиты локально:

```sh
cat /etc/firefox-vpn/initial-login.txt
```

Не публикуйте вывод, данные аккаунтов или снимки терминала без удаления секретов. Пароль создаётся при первой установке и сохраняется при повторной.

## 5. Добавление аккаунта

Обновите LuCI и откройте **Services → Firefox VPN**, обращаясь к LuCI по LAN IPv4. HTTP-панель откроется в той же вкладке. Управление только по IPv6 и доступ через путь обратного прокси этой интеграцией не охватываются.

Войдите с реквизитами панели, откройте **Accounts → Add account**, пройдите проверки почты, двухфакторной аутентификации или CAPTCHA. Нажмите **Test connection**. `Connection OK` означает успех тестового запроса, а не измерение задержки. Пароли панели, прокси и аккаунта Mozilla различаются.

## 6. PassWall2

**До выбора узла Firefox отключите Localhost Proxy в PassWall2 → Basic Settings и выполните Save & Apply.** Иначе исходящий запрос ядра может вернуться в само ядро. Проксирование клиентов LAN оставьте включённым. Эта настройка влияет и на трафик самого роутера с другими узлами; автоматически она не восстанавливается.

В **Node List → Add**:

| Поле | Значение |
| --- | --- |
| Remarks | Firefox VPN |
| Type | Xray |
| Protocol | Socks |
| Address | 127.0.0.1 |
| Port | 10810 |
| Username / Password | Реквизиты прокси, не панели и не Mozilla |
| TLS | Off |
| Transport | RAW (TCP) |
| Mux | Off |
| Chain Proxy | Close / Not use |

Прочитайте только реквизиты прокси локально:

```sh
jsonfilter -i /etc/firefox-vpn/config.json -e '@.proxy.username' -e '@.proxy.password'
```

Не делитесь выводом. Сохраните узел, выберите его в Basic Settings и примените. Проверьте с клиента LAN, отключив его VPN и альтернативные подключения. При сбое вернитесь к рабочему узлу.

## Работа и диагностика

Закрытие терминала не останавливает службу. `Sleeping` после простоя может быть нормальным: запрос или Test connection должен разбудить туннель. Запущенная служба не означает работающий туннель или доступ в Интернет.

| Симптом | Проверка |
| --- | --- |
| Предупреждение о петле или нет Интернета после выбора узла | Отключите Localhost Proxy и перезапустите ядро |
| Панель работает, LAN — нет | Реквизиты прокси, правила LAN в PassWall2 и DNS |
| Sleeping | Выполните реальный запрос перед сообщением об ошибке |
| Could not fetch | Служба, доступ по LAN IPv4 и HTTP-адрес панели |
| UDP refused | Ядро поддерживает только TCP |
| Нет пункта LuCI | Обновите LuCI, проверьте результат установки и службу |

```sh
/etc/init.d/firefox-vpn status
/etc/init.d/firefox-vpn restart
sh /usr/lib/firefox-vpn/diagnose.sh
```

Диагностика выводит только выбранные поля платформы, не читает файлы аккаунтов и конфигурации и ничего не отправляет. Перед публикацией проверьте даже этот вывод. Полный `logread` оставьте приватным; отправляйте только нужный фрагмент с вручную удалёнными секретами.

Выполните [список тестов](TESTING.ru.md), включая перезагрузку в удобное время. Считайте её успешной только после восстановления браузинга без ручного запуска ядра.

## Удаление

Сначала выберите другой рабочий узел PassWall2. Из распакованной папки:

```sh
sh uninstall.sh en
```

В новой сборке с переводом можно использовать `sh uninstall.sh ru`. Аккаунты в `/etc/firefox-vpn` сохраняются. Удаление всех аккаунтов не предусмотрено. Автообновления ядра нет: используйте проверенные релизы проекта, а не настольный обновлятор или универсальный Linux-установщик.

# راهنمای نصب

[English](INSTALL.md) · [فارسی](INSTALL.fa.md) · [Русский](INSTALL.ru.md) · [العربية](INSTALL.ar.md) · [جدول سازگاری](COMPATIBILITY.fa.md)

کد منبع نصب‌کننده از ⁦`--lang en|fa|ru|ar`⁩ پشتیبانی می‌کند. آرشیوهای منتشرشدهٔ ⁦v0.2.0-rc.1⁩ همچنان نصب‌کنندهٔ قبلی فارسی و انگلیسی دارند. در ساخت جدیدِ دارای ترجمه، می‌توان از ⁦`--lang ru`⁩ یا ⁦`--lang ar`⁩ و برای حذف از ⁦`sh uninstall.sh ru`⁩ یا ⁦`sh uninstall.sh ar`⁩ استفاده کرد. فایل‌های نصب نسخه‌های مختلف را با هم ترکیب نکنید.

## پیش‌نیازها

- فریم‌ور خانواده ⁦OpenWrt⁩، رابط ⁦LuCI⁩، سرویس ⁦procd⁩، معماری مناسب، دسترسی ⁦root⁩ و حداقل ۴۰ مگابایت فضای آزاد دائمی؛ فایل‌های بزرگ‌تر ممکن است فضای بیشتری لازم داشته باشند.
- حساب ⁦Mozilla / Firefox⁩، دسترسی به ایمیل و روش‌های تأیید آن.
- اینترنت کارای روتر؛ دسترسی به سرویس و سرورها برای همه حساب‌ها تضمین نیست.
- نصب جداگانه ⁦PassWall2⁩ برای عبور ترافیک دستگاه‌های شبکه.
- امکان بازگشت به نود سالم قبلی. نصب‌کننده تنظیمات شبکه، فایروال، ⁦DNS⁩ یا ⁦PassWall2⁩ را تغییر نمی‌دهد.

روی نصب کارای قدیمی ⁦test1⁩ نصب نکنید؛ مهاجرت خودکار نداریم. نصب‌کنندهٔ جدید هنوز روی روتر واقعی تأیید نشده است.

## ۱. ورود به روتر

از کامپیوتر، گوشی یا هر دستگاه دارای کلاینت ⁦SSH⁩ استفاده کنید:

```sh
ssh root@ROUTER_ADDRESS
```

عبارت ⁦ROUTER_ADDRESS⁩ جای‌نگهدار است؛ فقط روی دستگاه خودتان با آدرس روتر جایگزین کنید و آن را منتشر نکنید. ترمینال ⁦LuCI⁩، در صورت نصب، روش دیگری است. از شبکه مورد اعتماد یا مسیر مدیریتی امن موجود استفاده کنید؛ نیازی به بازکردن پورت روی اینترنت نیست.

## ۲. دریافت، کنترل و انتقال فایل

از خروجی ساخت موفق یا انتشار بازبینی‌شده، آرشیو مناسب پردازنده و فایل متناظر با پسوند ⁦sha256⁩ را بگیرید. روی کامپیوتر و در پوشه فایل‌ها:

```sh
sha256sum -c firefox-vpn-openwrt-v0.2.0-rc.1-linux-armv7.tar.gz.sha256
```

این مثال ⁦ARMv7⁩ است؛ برای معماری دیگر نام فایل را عوض کنید. ⁦checksum⁩ سلامت فایل را کنترل می‌کند و به‌تنهایی تأیید مستقل اعتبار ناشر نیست.

فایل را با فایل‌منیجر ⁦LuCI⁩، ⁦WinSCP⁩ یا ⁦SCP⁩ در مسیر /⁦root⁩ بارگذاری کنید:

```sh
scp firefox-vpn-openwrt-v0.2.0-rc.1-linux-armv7.tar.gz root@ROUTER_ADDRESS:/root/
```

اگر کلاینت ⁦OpenSSH⁩ خطای نبود ⁦SFTP⁩ داد، از گزینهٔ `scp -O` یا روش انتقال دیگری استفاده کنید. آرشیو را در ⁦Flash Firmware⁩، ⁦Restore Backup⁩ یا مدیر بسته بارگذاری نکنید.

## ۳. بررسی بدون نصب

روی روتر:

```sh
cd /root
tar -xzf firefox-vpn-openwrt-v0.2.0-rc.1-linux-armv7.tar.gz
cd firefox-vpn-openwrt
sh install.sh --lang fa --check
```

برای محیطی غیر از ترکیب دقیق مدل، نسخه و ⁦target⁩ مرجع:

```sh
sh install.sh --lang fa --experimental --check
```

گزینهٔ `--check` چیزی نصب نمی‌کند. نتیجهٔ موفق، فقط عبور از کنترل پیش‌نیازها است؛ ورود حساب، مسیریابی، ریبوت یا سازگاری عملی را تأیید نمی‌کند.

خانواده‌های خارج از ⁦OpenWrt⁩ و ⁦ImmortalWrt⁩ حتی با گزینهٔ آزمایشی پذیرفته نمی‌شوند. فریم‌ور ⁦GL.iNet⁩ باید خود را از خانوادهٔ پذیرفته‌شده معرفی کند و سرویس‌های لازم را داشته باشد؛ نام برند کافی نیست.

## ۴. نصب

روی محیط مرجع:

```sh
sh install.sh --lang fa
```

روی محیط آزمایشی با پذیرش آگاهانه:

```sh
sh install.sh --lang fa --experimental
```

داده حساب‌های موجود حفظ می‌شود. در نصب تازه، پراکسی روی `127.0.0.1:10810` و پنل ⁦HTTP⁩ روی آدرس ⁦IPv4⁩ شبکه داخلی و پورت 10820 تنظیم می‌شوند. تنظیمات قبلی بازنویسی نمی‌شوند؛ آدرس‌های گوش‌دادن آن‌ها را بررسی کنید.

اگر نصب پس از جایگزینی فایل‌های برنامه شکست بخورد، نصب‌کننده تلاش می‌کند نسخه قبلی همان فایل‌ها را بازگرداند. این قابلیت جایگزین بکاپ کامل روتر یا مهاجرت نیست.

مشخصات ورود اولیه، در صورت ایجاد، خصوصی روی روتر ذخیره می‌شود:

```sh
cat /etc/firefox-vpn/initial-login.txt
```

خروجی این دستور، داده حساب‌ها و تصویر بدون پوشش اطلاعات ترمینال را منتشر نکنید. رمز در نصب نخست تولید و در نصب مجدد حفظ می‌شود.

## ۵. افزودن حساب

با آدرس ⁦IPv4⁩ شبکه داخلی وارد ⁦LuCI⁩ شوید، صفحه را تازه‌سازی و ⁦Services → Firefox VPN⁩ را باز کنید. پنل ⁦HTTP⁩ در همان تب باز می‌شود. دسترسی مدیریتی صرفاً ⁦IPv6⁩ و دسترسی از مسیر ⁦reverse proxy⁩ در دامنه این یکپارچه‌سازی نیست.

با مشخصات پنل وارد شوید؛ سپس ⁦Accounts → Add account⁩ را انتخاب و مراحل ایمیل، تأیید دومرحله‌ای یا ⁦CAPTCHA⁩ را در صورت درخواست کامل کنید. ⁦Test connection⁩ را بزنید. پیام ⁦Connection OK⁩ موفقیت درخواست آزمایشی را نشان می‌دهد؛ زمان آن پینگ نیست.

ورود پنل، نام کاربری و رمز پراکسی، و حساب موزیلا سه مورد جدا هستند.

## ۶. تنظیم ⁦PassWall2⁩

**پیش از انتخاب نود فایرفاکس، در ⁦Basic Settings⁩ گزینه ⁦Localhost Proxy⁩ را خاموش و ⁦Save⁩ & ⁦Apply⁩ کنید.** در غیر این صورت اتصال خود هسته می‌تواند دوباره به همان هسته برگردد و حلقه ایجاد کند. پراکسی دستگاه‌های ⁦LAN⁩ روشن بماند. این تغییر روی ترافیک خود روتر هنگام استفاده از نودهای دیگر هم اثر دارد و خودکار برگردانده نمی‌شود.

در ⁦Node List → Add:⁩

| فیلد | مقدار |
| --- | --- |
| ⁦Remarks⁩ | ⁦Firefox VPN⁩ |
| ⁦Type⁩ | ⁦Xray⁩ |
| ⁦Protocol⁩ | ⁦Socks⁩ |
| ⁦Address⁩ | 127.0.0.1 |
| ⁦Port⁩ | 10810 |
| ⁦Username / Password⁩ | مشخصات پراکسی؛ نه پنل و نه حساب موزیلا |
| ⁦TLS⁩ | خاموش |
| ⁦Transport⁩ | ⁦RAW (TCP)⁩ |
| ⁦Mux⁩ | خاموش |
| ⁦Chain Proxy⁩ | ⁦Close / Not use⁩ |

برای دیدن فقط مشخصات پراکسی روی دستگاه خودتان:

```sh
jsonfilter -i /etc/firefox-vpn/config.json -e '@.proxy.username' -e '@.proxy.password'
```

خروجی را منتشر نکنید. نود را ذخیره و در ⁦Basic Settings⁩ انتخاب و اعمال کنید. روی دستگاه متصل به ⁦LAN⁩، ⁦VPN⁩ محلی و مسیرهای جایگزین اینترنت را غیرفعال و مرور وب را تست کنید. اگر اتصال برقرار نشد، نود سالم قبلی را برگردانید.

## نگهداری و عیب‌یابی

بستن ترمینال سرویس را خاموش نمی‌کند. حالت ⁦Sleeping⁩ پس از بی‌کاری می‌تواند طبیعی باشد؛ درخواست واقعی یا ⁦Test connection⁩ باید تونل را بیدار کند. اجرای سرویس به معنی فعال‌بودن تونل یا کارکرد اینترنت نیست.

| نشانه | بررسی پیشنهادی |
| --- | --- |
| هشدار ⁦loop⁩ یا قطع اینترنت پس از انتخاب نود | خاموش‌کردن ⁦Localhost Proxy⁩ و راه‌اندازی مجدد هسته |
| پنل کار می‌کند ولی اینترنت کاربران قطع است | مشخصات پراکسی، قوانین ⁦LAN⁩ و تنظیمات ⁦DNS⁩ پسوال |
| ⁦Sleeping⁩ | پیش از گزارش خطا، درخواست واقعی ایجاد کنید |
| ⁦Could not fetch⁩ | وضعیت سرویس، دسترسی ⁦IPv4⁩ داخلی و آدرس ⁦HTTP⁩ پنل |
| ⁦UDP refused⁩ | محدودیت ⁦TCP⁩ هسته اصلی |
| نبود منوی ⁦LuCI⁩ | تازه‌سازی صفحه و بررسی خروجی نصب و وضعیت سرویس |

```sh
/etc/init.d/firefox-vpn status
/etc/init.d/firefox-vpn restart
sh /usr/lib/firefox-vpn/diagnose.sh
```

گزارش عیب‌یابی فقط چند مشخصهٔ انتخاب‌شده را چاپ می‌کند؛ تنظیمات حساب و لاگ‌ها را نمی‌خواند و چیزی ارسال نمی‌کند. پیش از انتشار، همین خروجی را هم بازبینی کنید. خروجی کامل ⁦logread⁩ خصوصی است؛ فقط بخش مرتبط را پس از حذف دستی اطلاعات حساس منتشر کنید.

[چک‌لیست تست](TESTING.fa.md)، از جمله ریبوت در زمان مناسب، را اجرا کنید. تنها زمانی تست ریبوت را موفق ثبت کنید که مرور وب بدون روشن‌کردن دستی سرویس برقرار شده باشد.

## حذف

ابتدا نود سالم دیگری در ⁦PassWall2⁩ انتخاب کنید؛ سپس از پوشهٔ استخراج‌شده:

```sh
sh uninstall.sh fa
```

حساب‌ها و تنظیمات در /⁦etc/firefox-vpn⁩ حفظ می‌شوند؛ دستور حذف کامل حساب ارائه نشده است. به‌روزرسانی خودکار هسته نداریم؛ از نسخه‌های بازبینی‌شده همین پروژه استفاده کنید، نه به‌روزرسان دسکتاپ یا نصب‌کننده عمومی لینوکس هسته اصلی.
